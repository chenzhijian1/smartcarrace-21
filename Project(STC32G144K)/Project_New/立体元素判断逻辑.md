# 立体元素判断逻辑

本文档说明 `Project_New` 融合立体元素后的当前判断流程、状态转换、控制约束和安全策略。

相关源码：

- 路线管理：[element.c](user/src/element.c)、[element.h](user/inc/element.h)
- 公共姿态：[spatial_features.c](user/src/spatial_features.c)、[spatial_features.h](user/inc/spatial_features.h)
- 跷跷板：[seesaw.c](user/src/seesaw.c)、[seesaw.h](user/inc/seesaw.h)
- 圆筒：[cylinder.c](user/src/cylinder.c)、[cylinder.h](user/inc/cylinder.h)
- 环岛：[huandao.c](user/src/huandao.c)、[huandao.h](user/inc/huandao.h)
- 墙面：[wall.c](user/src/wall.c)、[wall.h](user/inc/wall.h)
- 车辆控制：[car_control.c](user/src/car_control.c)
- 电机与前馈：[my_motor.c](user/src/my_motor.c)

## 1. 总体结构

当前路线固定为：

```text
跷跷板 -> 圆筒 -> 环岛 -> 墙面 -> DONE
```

路线数组定义在 `element.c` 顶部：

```c
static const element_type_t element_route[] =
{
    ELEMENT_SEESAW,
    ELEMENT_CYLINDER,
    ELEMENT_HUANDAO,
    ELEMENT_WALL,
};
```

系统不会让四种元素同时竞争识别。管理器只更新当前路线元素对应的状态机，因此非当前元素的传感器特征不能推进路线。

元素完成后，管理器依次执行：

1. 校验完成事件是否来自当前元素。
2. 将电机重力前馈清零。
3. 路线下标加一。
4. 复位下一元素状态机。
5. 路线结束后进入 `ELEMENT_DONE`，保持普通循迹，不再启动元素识别。

修改路线时，只需调整 `element_route[]` 的元素顺序；允许增加、删除或重复同类元素。

## 2. 数据更新时序

### 2.1 IMU数据

IMU标称每 5 ms 更新一次：

```text
IMU660RC原始数据
    -> Quaternion/IMU_Update_Dt
    -> imu_sample_t（直接提供 ax/ay/az）
    -> 当前元素 IMU 状态机
    -> 重力前馈发布
```

如果主循环发生延迟，`gyro_update_ticks` 会累积丢失的 5 ms 周期，姿态更新使用实际累计时间补偿。

### 2.2 电感数据

电感约每 10 ms 更新一次：

```text
ADC采样
    -> direction_adc_get
    -> 更新AD_ONE[]、ad_ave[]和循迹误差
    -> Element_AdcUpdate
    -> 当前圆筒或环岛检测器
```

圆筒直接读取已有的 `ad_ave[0]`、`ad_ave[1]`、`ad_ave[3]`、`ad_ave[4]`，不使用额外的电感帧结构体。

## 3. 公共姿态工具

`spatial_features.c/.h` 现在只保留无状态的小工具，不保存姿态快照：

- `spatial_accel_vector_norm_in_range()`：用三轴加速度平方和与阈值平方比较，
  判断 `0.85g <= norm <= 1.15g`，不调用开方。
- `spatial_absf()`：绝对值工具。
- `spatial_clamp_i16()`：控制目标限幅工具。
- `spatial_confirm_update()`：连续帧确认计数工具。

跷跷板和墙面直接读取当前 `imu_sample_t.ax_g/ay_g/az_g`。平面判断为
`|ay| <= 0.15g && az >= 0.85g`，倒置和各阶段姿态也使用当前原始换算值，
不再使用低通、滞回标志或缓存的上仰角。

跷跷板和墙面的入口使用姿态解算得到的 `euler.pitch`。当前实车符号约定为：

```text
车头抬起：pitch < 0
车头下降：pitch > 0
```

## 4. 跷跷板

状态流程：

```text
IDLE -> RISING -> FALLING -> ACTIVE -> EXITED
```

### 4.1 建立基线

`IDLE` 状态下，必须连续 5 个IMU帧处于平面，才建立平面基线。基线建立前不接受跷跷板入口。

### 4.2 进入RISING

连续 5 帧同时满足以下条件：

- 平面基线已经建立
- 加速度模长有效
- `az >= 0.25g`
- `pitch <= -3度`
- `|pitch| <= 40度`

满足后进入 `RISING`，并开始记录最大抬起角度。

### 4.3 确认转折

上升阶段记录的最大 `|pitch|` 必须达到至少 8 度。随后：

1. 连续 3 帧 `pitch >= +3度`，从 `RISING` 进入 `FALLING`。
2. 再连续 3 帧保持正pitch，从 `FALLING` 进入 `ACTIVE`。
3. `ACTIVE` 状态下连续 3 帧回到平面，进入 `EXITED`。

管理器检测到 `EXITED` 后，将路线推进到圆筒。

### 4.4 候选撤销

以下情况会撤销候选并回到 `IDLE`：

- 姿态倒置
- `|pitch| > 40度`
- `az < 0.25g`
- 加速度模长连续无效达到 5 帧
- 候选持续超过 `SEESAW_MAX_CANDIDATE_SAMPLES`

当前 `SEESAW_MAX_CANDIDATE_SAMPLES=10`，按 5 ms 一帧计算约为 50 ms。该值较紧，实车调试时需要重点观察。

### 4.5 控制影响

只有 `RISING` 阶段限制速度：

- 整车目标速度最高为普通直线速度的 60%
- 左右轮目标限制在中心速度的 50%～150%
- 正向运行时单轮目标最低不低于 100

进入 `FALLING` 后立即释放低速限制，恢复普通循迹速度。

## 5. 圆筒

状态流程：

```text
IDLE -> PRE_ENTRY -> ON_CYLINDER -> EXIT_STRAIGHT -> 退出
```

### 5.1 电感入口

每个ADC帧计算：

```c
horizontal_sum = ad_ave[0] + ad_ave[4];
total_sum = horizontal_sum + ad_ave[1] + ad_ave[3];
```

连续 8 个ADC帧满足以下条件后，从 `IDLE` 进入 `PRE_ENTRY`：

- `horizontal_sum >= 3800`
- `total_sum >= 4200`
- `ad_ave[0] >= 1100`
- `ad_ave[4] >= 1100`

### 5.2 登筒

`PRE_ENTRY` 状态下，连续 5 个IMU帧 `pitch < -5度`，进入 `ON_CYLINDER`。

入口阶段限制方向差速：

- 向左差速最大为 `3`
- 向右差速最大为 `160`

当前入口角度保护配置为 `0度`，所以主要限制发生在 `PRE_ENTRY` 阶段。

### 5.3 筒面运动证据

进入筒面后，对 `|gyro_x|` 积分得到旋转进度，小于 `1 dps` 的角速度按零漂忽略。

顶部证据满足任一条件即可锁存：

- 旋转进度达到 90 度
- 连续 5 帧 `az <= -0.70g`

后半圈证据满足任一条件即可锁存：

- 旋转进度达到 210 度
- 已确认顶部，并连续 5 帧 `ay >= 0.50g`

旋转进度达到 300 度且已确认后半圈时，状态进入 `EXIT_STRAIGHT`。

### 5.4 出口确认

已到达至少 270 度或已经确认后半圈后，连续 8 个IMU帧满足以下条件：

- `|gyro_x| <= 70 dps`
- `pitch <= 60度`
- `az >= 0.60g`

满足后锁存退出状态，管理器将路线推进到环岛。

圆筒出口不再使用电感辅助，完全由运动进度和IMU姿态确认。

### 5.5 风机控制

`Cylinder_IsOnSurface()` 从0变为1时，风机只增压一次，目标为 `suction_fan_pwm_cylinder`。

离开筒面时：

- 正常情况下恢复 `suction_fan_pwm_start`
- 如果低压、停车或其他安全逻辑已经关闭风机，则不自动重新启动
- 如果当前风机功率已经被其他逻辑修改，也不会擅自恢复

### 5.6 重力前馈

圆筒筒面前馈为：

```text
feedforward_pwm = -1600 * sin(pitch)
```

前馈同时加到左右电机PWM，用于抵消沿圆筒切向的重力分量，不改变左右差速方向。

### 5.7 单侧饱和保护

只有当前元素为圆筒且车辆处于筒面时才累计：

- 单侧PWM达到 `9500`
- 同侧速度误差大于 `80`
- 当前方向差速继续加重该侧负担
- 连续持续 20 个 5 ms 控制周期，即约 100 ms

确认饱和后，将对应方向的差速缩小到原来的 50%。离开筒面后，饱和计数和保护标志全部复位。

## 6. 环岛

检测状态流程：

```text
NORMAL -> SUSPECT -> ACTIVE -> REARM
```

车辆控制流程：

```text
预环岛 -> 入环 -> 环内循迹 -> 出环直行 -> 退出事件
```

### 6.1 入口候选

正常循迹时，连续 3 个ADC帧满足：

- `AD_ONE[0] > 33`
- `AD_ONE[4] > 33`

进入 `SUSPECT`。候选阶段：

- 清零方向误差
- 强制车辆直行
- 保存候选起点编码器距离

### 6.2 方向确认

候选阶段分别检查：

- 左侧：`AD_ONE[0] > 55`
- 右侧：`AD_ONE[4] > 55`

任意一侧连续 3 帧成立后确认环岛。方向可以使用传感器判断，也可以按 `huandao_dir[]` 的预设方向覆盖。

如果候选行驶距离超过 350 仍未确认，则放弃候选并进入重新布防。

### 6.3 环岛行驶与退出

1. 预环岛阶段按照 `distance_before_huandao[]` 直行。
2. 航向角变化 60 度后进入环内循迹。
3. 环内累计航向变化 280 度后进入出口直行。
4. 出口继续直行 250 编码器距离。
5. 产生一次性退出事件并重新布防。
6. 管理器消费退出事件，将路线推进到墙面。

## 7. 墙面

状态流程：

```text
IDLE -> CLIMB_CANDIDATE -> VERTICAL_PROVISIONAL
     -> LATERAL -> DESCENT -> EXITED
```

### 7.1 基线与上坡入口

连续 5 帧处于平面后建立基线。随后连续 5 帧满足：

- 加速度模长有效
- `pitch < -5度`

进入 `CLIMB_CANDIDATE`。

### 7.2 近竖直阶段

连续 10 帧满足：

- `ay <= -0.75g`
- `az <= 0.45g`
- `az > -0.35g`
- `|ax| <= 0.70g`

进入 `VERTICAL_PROVISIONAL`。此时仍不能正式确认墙面，因为圆筒也可能经过近竖直姿态。

### 7.3 横向确认

连续 10 帧满足：

- `|ax| >= 0.70g`
- `|ay| <= 0.45g`
- `|az| <= 0.45g`

进入 `LATERAL`。重力主要落在轮轴方向后，才正式确认这是墙面而不是圆筒。

### 7.4 下坡与退出

`LATERAL` 状态下，连续 5 帧满足：

- `ay >= 0.45g`
- `|ax| <= 0.60g`
- `az > -0.35g`

进入 `DESCENT`。

随后连续 20 帧满足：

- 已经见过横向阶段
- 当前 `imu_sample_t` 直接满足平面条件：`|ay| <= 0.15g`、`az >= 0.85g`
- 加速度模长有效

进入 `EXITED`，路线推进到 `DONE`。

如果横向后的下坡过渡很短，`LATERAL` 状态连续 20 帧稳定回平也可以直接确认退出。

### 7.5 候选撤销

以下情况会撤销候选并返回 `IDLE`：

- 确认墙面前重新回到平面
- 当前 `az <= -0.35g`
- 加速度模长连续无效达到 8 帧
- 候选持续超过 2400 帧，约 12 秒

### 7.6 控制影响

- 上坡候选阶段速度上限：普通直线速度的 80%
- 近竖直阶段速度上限：75%
- 横向阶段速度上限：90%
- 墙面进行中限制单轮目标，防止某一侧轮速反向

墙面候选到下坡阶段使用：

```text
feedforward_pwm = -1600 * sin(pitch)
```

## 8. 前馈发布和安全清零

元素管理器在每个IMU帧完成状态更新后，根据更新后的当前元素发布前馈：

- 当前元素为圆筒：按当前筒面状态直接计算前馈
- 当前元素为墙面：按当前墙面状态直接计算前馈
- 跷跷板、环岛、`DONE`：发布0

圆筒和墙面模块不再保存前馈快照，计算结果直接写入电机层已有的双缓冲。

以下情况强制发布0：

- 低压保护生效
- `flag==4`，处于发车等待阶段
- `normal_speed==0` 且不处于软停车过程
- 元素完成和路线切换
- 元素状态机复位

此外，`motor_control_stop()` 会再次独立清零前馈。管理器和电机停止路径形成两层保护。

## 9. 控制链中的作用位置

正常循迹控制链为：

```text
方向PID
    -> 圆筒单侧饱和差速保护
    -> 元素速度/方向约束
    -> speed_adjust计算左右轮目标
    -> 元素单轮目标限幅
    -> 电机速度PID
    -> 左右轮共同重力前馈
    -> PWM最终限幅
```

各元素不会替换原方向PID、速度PID或普通循迹参数，只在对应阶段叠加速度上限、差速保护、轮速保护、风机控制和重力前馈。

## 10. 串口观察

### t4：路线与状态

依次输出：

```text
路线下标,当前元素,跷跷板状态,圆筒状态,墙面状态,pitch
```

元素编号：

```text
0=SEESAW
1=CYLINDER
2=HUANDAO
3=WALL
4=DONE
```

### t5：圆筒调试

依次输出：

```text
ad_ave[0],ad_ave[1],ad_ave[3],ad_ave[4],pitch,
圆筒入口标志,筒面标志,退出标志,
当前风机PWM,圆筒目标风机PWM,实际电机前馈PWM
```

普通循迹、跷跷板、环岛和 `DONE` 阶段，实际电机前馈PWM应为0。
